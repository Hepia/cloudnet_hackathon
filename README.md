# 6G-DALI / NATWORK Hackathon — 5G DDoS detection

A self-contained **5G DDoS-detection hackathon**: a Dockerised 5G testbed that
generates **real** mixed benign + DDoS traffic, scripts that capture and label it into
datasets, and a CNN detector that classifies every packet as benign or attack.

The contribution on this branch is a **per-packet CNN detector** that meets the NATWORK
KPIs (false positives < 1 %, false negatives < 1 %), plus the dataset-generation
campaign and the lab fix that make it reproducible.

> **What the attack is:** the testbed's pluggable traffic generator is loaded with a real
> **Mirai botnet** (CNC + bot). The Mirai bot runs inside the **5G UE's** network
> namespace, so its **SYN flood crosses the real 5G user plane** (UE → gNB → UPF →
> router → target), interleaved with a legitimate HTTP/MQTT/video/iperf application mix.
> The 5G UE runs *only* the bot, so a packet is DDoS exactly when it touches the UE
> address — an unambiguous ground-truth label.


> The raw captures (~15 GB of pcap) and the composed windowed dataset (~2.7 GB HDF5) are
> **not committed** — too large for GitHub, and regenerated by `REPRODUCE.md`. The trained
> model itself is small and **is** committed.

## The result in one line

The new per-packet model passes both NATWORK KPIs (FP 0.0001 %, FN 0.009 %) where the
shipped global-window model fails (FP 55.7 %, FN 36.7 %) — because it classifies each
packet independently instead of blending the whole window. Full table and the *why* are
in [`ddos_cnn_xgb/README.md`](ddos_cnn_xgb/README.md) and
[`ddos_cnn_xgb/bigrun/README.md`](ddos_cnn_xgb/bigrun/README.md).

## Quick start

```bash
cd infrastructure && ./lab.sh up            # build + start the lab (see infrastructure/README.md)
../datasets/generate_final.sh big 15 60     # capture a dataset   (see datasets/README.md)
cd ../ddos_cnn_xgb && ./run_final_pipeline.sh ../datasets/pcap_big bigrun   # train + evaluate
```
